# Лабораторная работа 3. JavaScript. Зоомагазин · вариант 1

Проект продолжает LR2: слайдер на классах, светлая/тёмная тема,
интерактивная таблица сотрудников, конструктор текстовых полей,
пагинация каталога, объёмные карточки, расчёт возраста, две реализации
наследования, синтез речи, график ряда в Chart.js и анимация при прокрутке.

Требования PDF и порядок показа: [docs/LR3_CHECKLIST.md](docs/LR3_CHECKLIST.md).
Ветка: `STRWEB_LR3_JS`. LR2 остаётся самостоятельной работой.

## Локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver
```

После запуска откройте `http://127.0.0.1:8000/`. Демо-аккаунт покупателя: `buyer` / `buyer12345`; администратора: `admin` / `admin12345`.

Страница `/html-demo/` собирает примеры тегов из задания: списки, таблицу с `headers`, форму с HTML-валидацией, iframe, видео и аудио.

## Проверки

```bash
python manage.py test
coverage run manage.py test
coverage report
```

Основные страницы LR3:

- `/` — слайдер; настройки доступны admin после входа.
- `/employees/` — контакты из БД с поиском, сортировкой и страницами по 3.
- `/products/` — каталог, страницы по 3/6/9 товаров.
- `/js-lab/` — конструктор, возраст, наследование, Web Speech API и Chart.js.

Для JS-вычислений: `node --test tests/lr3-core.test.cjs`.
Для полного набора Python-проверок: `python -m pytest -q`.
Браузерные проверки описаны в [чек-листе](docs/LR3_CHECKLIST.md).

Chart.js лежит в `static/vendor/`; интернет для построения графика не требуется.
Некоторые картинки товаров и шрифт, унаследованные от LR2, загружаются извне.

ER-диаграмма предметной области находится в `docs/entity_diagram.md`.

## Промокоды

Покупатель видит действующие и архивные промокоды на странице `/promos/`.
При покупке товара на странице `/products/<id>/buy/` можно ввести код в поле `Промокод`.
Сайт проверяет, что код существует, активен и не просрочен, после чего сохраняет его в продаже и пересчитывает итоговую сумму.

В демо-данных доступен промокод `PET10`.

## Остатки товаров

Количество товара на складе не хранится отдельным полем. Оно считается по фактическим операциям:

```text
остаток = сумма закупок товара - сумма проданных единиц товара
```

Закупки через `SupplyPurchase.quantity` пополняют склад, а продажи через `SaleItem.quantity` уменьшают остаток. Пользователь не может оформить покупку, если товара нет на складе или запрошенное количество больше остатка.

## Логирование

Уровень логирования берется из переменной окружения `LOG_LEVEL`, по умолчанию используется `INFO`.
Логи приложения `shop` пишутся в консоль и в `logs/petshop.log`.

Сейчас логируются регистрация, добавление отзывов, покупка товара, применение промокода, ошибки покупки, CRUD-операции сотрудников с товарами/поставщиками/закупками, обращения к защищенным API и сбои внешних API.
